# Rule: Strict Testing & Verification
**Activation:** Always On
**Glob:** `**/*.ts`, `**/*.tsx`

Когато изпълняваш Workflows за поправка на бъгове или добавяне на функционалност, СТРОГО спазвай тези правила:
1. **Unit тестове (Jest):** Пиши ги в папка `__tests__/` за всички API routes, валидации (Zod) и utility функции.
2. **E2E тестове (Playwright):** Пиши ги в папка `e2e/` за всички потребителски потоци (Login, Navigation, 404 страници).
3. **TDD Подход:** Първо анализирай проблема, напиши теста, поправи кода и след това стартирай теста в терминала.
4. **Доказателство:** Всеки фиксиран бъг трябва да има съответстващ тест, който доказва, че проблемът е решен.
5. Добави всички файлове и папките в .gitignore
